# Acceptance Criteria: Invoice Quote v0.2.1 Extended Writer

## 1. Назначение extended writer

Extended writer - это будущий writer для заранее подготовленного расширенного Excel-шаблона.

Он нужен для безопасной генерации 6+ / 30-50+ позиций в черновике КП без обхода ограничений старого MVP.

Extended writer не является финальным production-релизом.

Generated output остается черновиком.

Ручная проверка Excel обязательна перед любым использованием результата.

## 2. Границы ответственности

Extended writer должен:

* принимать flat payload;
* принимать layout/capacity расширенного шаблона;
* писать позиции только в разрешенный диапазон строк;
* не трогать итоги, примечания, подписи, шапку, реквизиты, drawing/media chain;
* создавать output только вне Git;
* не перезаписывать existing output;
* чистить temp/partial output при ошибке.

## 3. Writer mode

Будущая логика writer mode:

* старый MVP остается default writer для capacity 5;
* extended writer включается только явно;
* возможный будущий режим: `--writer mvp|extended`;
* `--template-capacity > 5` само по себе не разрешает запись старым MVP на 30-50 строк.

## 4. Layout / capacity model

Acceptance criteria:

* capacity должна быть явно задана или подтверждена layout/config;
* layout должен включать минимум:
  * `item_start_row`;
  * `item_end_row`;
  * `capacity`;
  * `total_row`;
  * `signature_range`;
  * `header_ranges`;
  * `formula_cells`;
  * protected/service ranges;
* если layout неизвестен или конфликтует с шаблоном, generation должна остановиться fail-closed.

## 5. Запрещенное поведение

Запрещено:

* просто снять лимит 5 в старом MVP;
* писать 6+ строк старым MVP;
* молча обрезать позиции;
* молча переносить позиции в примечания;
* писать поверх итогов, примечаний, подписей, шапки, реквизитов или media;
* добавлять реальные `.xlsx` в Git;
* делать динамическую вставку строк в первом extended writer step;
* считать generated output утвержденным КП;
* менять цену, срок, комплектацию или `project_spec`.

## 6. Тестовая стратегия

Будущие тесты должны проверять:

* тестовый расширенный шаблон создается кодом в `tmp_path`;
* `.xlsx` fixture не хранится в Git;
* 6+ позиций проходят только через explicit extended writer;
* при превышении capacity output не создается;
* existing output не перезаписывается;
* temp/partial output чистится при ошибке;
* формулы итогов сохраняются;
* формулы строк позиций сохраняются или корректно восстанавливаются;
* подписи сохраняются;
* шапка и реквизиты сохраняются;
* merged ranges сохраняются;
* drawing/media chain сохраняется;
* старый MVP остается неизменным по SHA256;
* старые сценарии на 5 строк не ломаются.

## 7. Human Approval Points

Отдельное подтверждение Игоря требуется на:

* изменение реального Excel-шаблона;
* выбор реального extended template;
* фактическую capacity реального шаблона;
* добавление `.xlsx` в Git;
* переход к manifest;
* переход к динамической вставке строк;
* изменение старого MVP;
* использование generated output как клиентского КП;
* отправку клиенту;
* финальную цену, срок, комплектацию.

## 8. Definition of Done

Документ считается готовым, если:

* создан только один markdown-файл acceptance criteria;
* код не менялся;
* tests не менялись;
* `.xlsx` не добавлялись;
* manifest не создавался;
* старый MVP не трогался;
* `git diff --check` чистый;
* документ согласован до commit.
