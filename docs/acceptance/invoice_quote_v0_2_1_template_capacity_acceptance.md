# Acceptance Criteria: Invoice Quote v0.2.1 Template Capacity

## 1. Назначение Этапа v0.2.1

v0.2.1 - это не финальный production-релиз, а безопасный шаг к поддержке
реальных КП с 30-50+ позициями на блок.

Цель этапа - перейти от временного safety guard на 5 позиций к проверенной
template capacity / extended rows модели, где генератор понимает ёмкость
выбранного Excel-шаблона и не пишет за безопасные границы.

Все generated output остаются черновиками. Ручная проверка Excel обязательна
перед любым решением о принятии output или отправке клиенту.

## 2. Template Capacity

Capacity шаблона должна быть явно определена или надёжно вычислена.

Acceptance criteria:

- если `items_count <= capacity`, генерация допустима;
- если `items_count > capacity`, скрипт должен остановиться без создания output;
- ошибка должна возникать до записи final output;
- запрещено затирать строки итогов;
- запрещено затирать примечания;
- запрещено затирать подписи;
- запрещено менять шапку и реквизиты;
- запрещено повреждать drawing/media chain.

Capacity не является бизнес-ограничением. Это техническая граница безопасной
записи в конкретный проверенный шаблон.

## 3. Расширенный Шаблон

Предпочтительный путь v0.2.1 - заранее подготовленный и проверенный расширенный
Excel-шаблон на 30-50+ строк.

Acceptance criteria:

- реальный `.xlsx` шаблон пока не добавляется в Git;
- реальные шаблоны хранятся вне Git до отдельного решения Игоря;
- для автотестов расширенный шаблон создаётся кодом в `tmp_path`;
- бинарный Excel-файл не хранится в репозитории как тестовый fixture;
- формулы, итог, примечания, подписи, шапка, layout и media заранее проверены в
  расширенном шаблоне.

## 4. Старый MVP

`scripts/fill_invoice_quote_draft.py` по умолчанию не менять без отдельного
решения.

Acceptance criteria:

- старый лимит 5 позиций остаётся safety guard старого MVP;
- v0.2.1 не ломает старые сценарии;
- старый MVP не начинает молча принимать 30-50+ позиций;
- если изменение старого MVP всё-таки потребуется, перед этим нужно отдельное
  решение Игоря и отдельный набор regression tests.

## 5. v0.2 Separate Layer

`separate_workbooks_by_block` должен получить безопасный путь к расширенной
capacity.

Acceptance criteria:

- capacity проверяется до генерации output;
- если блок помещается в capacity выбранного шаблона, output по блоку может быть
  создан;
- если блок превышает capacity выбранного шаблона, output по этому блоку не
  создаётся;
- если один блок не проходит capacity check, не создаётся частичный набор
  output-файлов;
- ошибка должна быть понятной и содержать block name, количество позиций и
  capacity шаблона.

Пример смысла ошибки:

```text
block orynbor_8 has 52 items, template capacity is 50
```

## 6. Запрещённое Поведение

Запрещено:

- просто заменить `MAX_ITEMS = 5` на `50`;
- молча обрезать позиции;
- молча переносить лишние позиции в примечания;
- создавать частичный КП без явной ошибки;
- писать поверх итогов, примечаний, подписей, шапки, реквизитов или media;
- менять цену, срок, комплектацию или `project_spec`;
- считать generated output подтверждённым КП;
- отправлять generated output клиенту без отдельного подтверждения;
- реализовывать динамическую вставку строк как часть первого шага v0.2.1.

## 7. Тесты

Будущие тесты v0.2.1 должны покрывать:

- блок с количеством позиций в пределах capacity создаёт output;
- блок с количеством позиций больше capacity останавливается без output;
- старый MVP остаётся неизменным по SHA256, если выбран путь без его изменения;
- итоговые формулы нового диапазона сохраняются;
- merged ranges сохраняются;
- signatures сохраняются;
- header/requisites сохраняются;
- drawing/media chain сохраняется;
- temp-файлы чистятся при ошибке;
- output внутри Git запрещён;
- existing output не перезаписывается;
- partial output не остаётся;
- расширенный тестовый шаблон создаётся в `tmp_path`;
- тестовый `.xlsx` не добавляется в Git.

## 8. Human Approval Points

Отдельного подтверждения Игоря требуют:

- изменение реального Excel-шаблона;
- добавление реального `.xlsx` шаблона в Git;
- снятие лимита 5 в старом MVP;
- переход от расширенного шаблона к динамической вставке строк;
- использование generated output как клиентского КП;
- отправка клиенту;
- финальная цена;
- финальный срок;
- комплектация;
- замены;
- закупка;
- запуск цеха.

## 9. Definition of Done

Этот acceptance criteria документ считается готовым, если:

- создан только один новый markdown-файл acceptance criteria;
- Python-код не менялся;
- tests не менялись;
- examples не менялись;
- Excel-файлы не добавлялись;
- реальные Excel-шаблоны не редактировались;
- PDF не трогались;
- `git diff --check` чистый;
- документ согласован по смыслу перед commit.

v0.2.1 code step начинается только после отдельного подтверждения.
