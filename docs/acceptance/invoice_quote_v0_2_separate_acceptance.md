# Acceptance Criteria: Invoice Quote v0.2 Separate Workbooks

## 1. Назначение

Этот документ фиксирует критерии успеха для ручного MVP-прогона режима
`separate_workbooks_by_block` и ревью результата.

Acceptance criteria нужны, чтобы отделить системные требования от промпта и
проверять результат одинаково при каждом запуске: от v0.2 JSON до отдельных
Excel output-файлов и ручного решения о принятии результата.

Документ не подтверждает финальные цены, сроки, комплектацию или проектные
данные. Все output-файлы остаются черновиками до отдельного подтверждения Игоря.

## 2. Scope

### Входит

- v0.2 JSON как входной контракт.
- Проверка JSON через `scripts/validate_invoice_quote_v0_2.py`.
- Режим `separate_workbooks_by_block`.
- Создание отдельного Excel output по каждому элементу `project_blocks[]`.
- Безопасность `output_dir` и output-файлов.
- Проверки CI и локальный quality gate.
- Текущий временный safety guard на 5 позиций после flatten subsections.

### Не входит

- OCR.
- Чтение PDF.
- Reconciliation.
- `single_workbook_sections`.
- Режим `both` как полный общий плюс раздельный вывод.
- Динамическая вставка строк.
- Финальные цены и сроки.
- Поддержка 30-50+ позиций.
- Расширенный Excel-шаблон.

## 3. Acceptance Checklist

- JSON проходит `validate_invoice_quote_v0_2`.
- `output_mode = separate_workbooks_by_block`.
- По каждому `project_block` создаётся отдельный `.xlsx` output.
- `output_dir` существует и находится вне Git-проекта.
- Существующие output-файлы не перезаписываются.
- Если любой output уже существует, не создаётся частичный набор файлов.
- Если в блоке больше 5 `items` после flatten subsections, output не создаётся.
- Лимит 5 `items` явно считается временным safety guard текущего MVP, а не
  целевым ограничением v0.2.
- `subsection_name` добавляется к `item.name` как префикс.
- Старый `scripts/fill_invoice_quote_draft.py` не изменяется.
- Excel-файлы не добавляются в Git.
- Формулы, шапка, реквизиты, подписи, логотип, drawings и media сохраняются.
- `pytest`, `ruff`, `black --check` и `mypy` проходят.
- GitHub Actions зелёный.
- Ручная проверка открытия output в Excel обязательна.
- Output остаётся черновиком.
- Цена, срок, комплектация и `project_spec` не считаются подтверждёнными.

## 4. Временный Лимит 5 Позиций И Будущая Поддержка 30-50+ Позиций

Лимит 5 позиций нужен только для безопасности текущего MVP.

Он не является бизнес-ограничением для реальных КП и не является целевым
ограничением v0.2. Реальные КП часто могут иметь 30, 40, 50 и более позиций.

Причина текущего лимита: безопасно проверенный шаблон и старый MVP-заполнитель
работают только с ограниченной областью строк. Если сейчас разрешить 30-50+
позиций без расширенного шаблона, есть риск затереть формулы, итоги, подписи,
примечания, область печати или другие части Excel-шаблона.

Текущий MVP не должен притворяться, что умеет безопасно писать больше строк.
Если после flatten subsections в одном блоке больше 5 `items`, скрипт должен
остановиться без создания output.

Следующий этап должен называться `template capacity / extended rows`.
Предпочтительный безопасный путь: заранее подготовленный и проверенный
расширенный шаблон на 30-50+ строк.

Динамическая вставка строк остаётся отдельным рискованным spike. Если количество
`items` больше проверенной template capacity, скрипт должен останавливаться без
создания output.

## 5. Manual Review Checklist

Игорь проверяет глазами в Excel:

- Файл открывается без восстановления.
- Логотип на месте.
- Шапка и реквизиты на месте.
- Блок или пятно видно в объекте или позиции проекта.
- Позиции перенесены.
- Цена не утверждена.
- Предупреждения о черновике видны.
- Формулы и итоги не сломаны.
- Подписи не повреждены.

## 6. Failure Conditions

Результат не принимается, если:

- Excel открывается с восстановлением.
- Пропал логотип.
- Output перезаписал существующий файл.
- Output создан внутри Git-проекта.
- `git status` содержит `.xlsx`.
- CI красный.
- Цена или срок выглядят как финальные без подтверждения.
- Скрипт изменил старый MVP без отдельного решения.
- Документ описывает лимит 5 позиций как постоянное ограничение v0.2, а не как
  временный safety guard.

## 7. Dependency Map

```text
v0.2 JSON
  -> validator
  -> separate filler
  -> Excel output
  -> manual review
  -> commit/push decision
```

## 8. Human Approval Points

Игорь отдельно подтверждает:

- Ручной MVP-прогон.
- Принятие output.
- Переход к расширенному шаблону на 30-50+ позиций.
- Переход к `single_workbook_sections`.
- Любые изменения в шаблоне.
- Любые финальные цены и сроки.
