# MVP-заполнитель черновика счёта-КП

## 1. Что делает MVP-заполнитель

`scripts/fill_invoice_quote_draft.py` заполняет черновик счёта-КП на
основе JSON-входа и Excel-шаблона.

Скрипт:

- принимает путь к `.xlsx` шаблону, путь к JSON и путь к выходному `.xlsx`;
- валидирует входные данные и правила безопасности;
- открывает шаблон через `openpyxl`;
- сохраняет результат только в новый output-файл;
- заполняет ограниченный набор разрешённых ячеек;
- не изменяет исходный шаблон;
- после сохранения проверяет, что критичные части шаблона не сломались.

Это инструмент для подготовки внутреннего черновика, а не для выпуска
финального коммерческого предложения клиенту.

## 2. Что MVP не делает

MVP-заполнитель не:

- утверждает финальную цену;
- утверждает срок поставки;
- генерирует сумму прописью;
- подключается к Реестру заявок;
- рассчитывает итоговые суммы в Python;
- добавляет Excel-файлы в Git;
- создаёт папку output автоматически;
- перезаписывает существующий output-файл;
- готовит документ к отправке клиенту.

## 5. Правила безопасности

Основные правила:

- исходный `template_test.xlsx` не изменять;
- output создавать только вне Git-проекта;
- Excel-файлы не добавлять в Git;
- финальную цену и срок не утверждать автоматически;
- формулы `I17:I22` не трогать;
- `H22:I22` напрямую не заполнять;
- `C24:I24` в MVP не генерировать;
- подписи `B32:I34` не трогать;
- шапку и реквизиты `C2:I6`, `B4:B6` не трогать;
- логотип, drawing parts и media parts не ломать.

Скрипт должен завершаться ошибкой, если output уже существует, output находится
внутри проекта, JSON невалидный или входные данные нарушают правила черновика.

## 6. Ограничения MVP

Текущие ограничения:

- максимум 5 позиций - это временное техническое ограничение первого MVP;
- лимит связан с текущим шаблоном, где безопасно проверены строки `17:21`;
- если во входном JSON больше 5 позиций, текущий MVP должен остановиться и не
  создавать output;
- это не ограничение будущих КП;
- цены не записываются числом;
- `H17:H21` для заполненных и безопасно добавленных строк получает
  `"нужно уточнить"`;
- `C24:I24` не генерируется;
- при JSON с меньшим количеством позиций оставшиеся строки до 21-й заполняются
  безопасными значениями:
  - `C`: `"нужно уточнить"`;
  - `D`: `"шт"`;
  - `E`: `1`;
  - `F`: `"нужно уточнить"`;
  - `G`: `"нужно уточнить"`;
  - `H`: `"нужно уточнить"`;
- Реестр заявок пока не подключён;
- документ является черновиком для внутренней проверки, а не финальным КП.

### Будущая поддержка проектов с блоками

В реальных проектах позиции могут быть разделены по блокам: `"Блок 1"`,
`"Блок 2"`, `"Паркинг"`, `"Административная часть"`,
`"Технические помещения"` и т.п.

Будущая версия должна уметь принимать структуру данных по блокам, например:

```json
{
  "project_blocks": [
    {
      "block_name": "Блок 1",
      "items": []
    },
    {
      "block_name": "Паркинг",
      "items": []
    }
  ]
}
```

Первый безопасный вариант реализации - не вставлять строки динамически, а
формировать отдельный черновик/output по каждому блоку или использовать заранее
расширенный шаблон.

Динамическая вставка строк возможна позже, но только после отдельного spike и
тестов, потому что она может повлиять на формулы, сетку, область печати,
подписи и merged cells.

## 7. Проверки после сохранения

После сохранения output-файла скрипт проверяет:

- output создан;
- исходный template не изменился по байтам;
- формулы `I17:I22` совпадают с шаблоном;
- merged ranges совпадают;
- подписи `B32:I34` совпадают;
- шапка и реквизиты `C2:I6`, `B4:B6` совпадают;
- цепочка логотипа worksheet -> drawing -> image сохранена;
- `xl/media/image1.png` существует и совпадает по байтам;
- `[Content_Types].xml` содержит нужные drawing/image content types;
- `scripts/inspect_excel_template.py` открывает output без ошибки.

Если хотя бы одна проверка не проходит, скрипт печатает `FAIL` и завершается с
кодом `1`.

## 8. Если output уже существует

Скрипт не перезаписывает существующий output-файл.

Если output уже существует:

- не удаляйте его автоматически;
- проверьте, нужен ли этот файл;
- выберите новое имя output-файла, например с суффиксом `_v2`;
- либо удалите старый файл вручную только после отдельного решения.

## 9. Если Excel открывается с восстановлением файла

Если Excel показывает восстановление файла при открытии output:

- не использовать такой output для дальнейшей работы;
- проверить PASS/FAIL-отчёт скрипта;
- проверить цепочку `sheet1.xml -> sheet1.xml.rels -> drawing1.xml ->
  drawing1.xml.rels -> image1.png`;
- убедиться, что логотип не стал orphan drawing/media part;
- выполнить `scripts/inspect_excel_template.py` на output;
- сравнить формулы, merged ranges, подписи, шапку и реквизиты с шаблоном;
- создать новый output после исправления причины.

Для текущего проверенного output
`invoice_quote_draft_mvp_output_v2.xlsx` визуальная проверка прошла: Excel
открыл файл без восстановления, логотип, шапка, реквизиты, сетка и подписи
остались на месте.

## 10. Следующие возможные этапы

Возможные дальнейшие шаги:

- подключить реальные данные заявки;
- сделать отдельный JSON на реальную заявку;
- поддержать группировку позиций по блокам проекта;
- подготовить расширенный шаблон на большее количество строк;
- отдельно исследовать безопасную вставку строк в Excel;
- научить скрипт формировать несколько output-файлов по блокам, если позиций
  больше 5;
- добавить `dry-run` режим;
- добавить отчёт о заполненных ячейках;
- расширить отчёт о проверках после сохранения;
- позже связать заполнение с Реестром заявок.
